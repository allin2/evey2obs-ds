evey2obs 隐私说明

evey2obs 的默认设计是本地优先：平台链接解析、音频转写、Markdown/JSON 导出和临时文件清理都在你的机器上完成。 只有当你配置大模型服务时，提取后的文本才会发送到该服务用于总结。

1. 默认会处理哪些数据

输入内容

你粘贴的分享链接、分享文案或本地音视频文件路径会用于识别来源和创建任务。

提取结果

公开正文、字幕、转写文本、图片附件、摘要和行动项会写入你配置的 Obsidian Vault。

配置

普通设置保存在平台配置目录；API Key 仅交给系统密钥链或从环境变量读取，不写入设置 JSON。

诊断

失败诊断包含任务状态、阶段、错误码和下一步建议，默认只导出失败任务。

转写缓存

系统缓存目录会保存可复用的正文、时间戳和模型名；不保存来源 URL、Cookie、token 或本地媒体路径。

待导出草稿

Vault 导出失败时，应用数据目录会临时保存可恢复的 Markdown、JSON 清单和附件副本；来源链接和本地文件引用会先脱敏，用户可在 GUI/CLI 中列出、恢复或删除。

2. 不应保存或外泄的数据

以下内容不得进入笔记、普通日志、测试夹具、异常堆栈或诊断报告：

  • API Key、Authorization、Cookie、密码、token 和 secret。
  • 浏览器 Cookie 数据库路径、Cookie 解密结果和账号凭据。
  • 分享追踪参数，例如 utm_*、share_id、shareRedId、appuid。
  • 本机敏感路径，例如个人主目录、临时目录和本地端口。
  • DRM、私密、付费墙、验证码或账号访问控制背后的内容。
evey2obs 不绕过访问控制。遇到公众号验证码、仅客户端可见或平台要求登录时，应提示用户复制正文、重新分享公开链接、导入本地文件，或在明确理解风险后授权 Cookie。

部分公开分享链接包含抓取所需 token。该 token 只在平台适配器内部访问内容，发送给模型或写入笔记、JSON、CLI、诊断前会从 URL 中删除。

3. 大模型请求边界

当你运行总结或完整导出流程时，提取出的正文/字幕会发送给你配置的大模型服务。 evey2obs 不内建云端账号或计费；你选择的 Base URL 和 API Key 决定实际服务方。

会发送不会主动发送
待总结的正文、字幕、提示词和模型名。 API Key 明文、Cookie、浏览器 Cookie 文件、本地 Vault 路径。

4. Cookie 与认证

默认不读取浏览器 Cookie。只有平台确实要求登录，且用户明确授权后，才应使用 高级设置中的浏览器 Cookie 选项，或使用 EVEY2OBS_YTDLP_COOKIES_FROM_BROWSER / EVEY2OBS_YTDLP_COOKIES_FILE。

  • 优先使用公开链接、官方字幕、公开正文或本地文件。
  • 授权 Cookie 前，应说明账号隐私和平台风控风险。
  • Cookie 值、Cookie 文件内容和浏览器数据库路径不得进入日志或导出笔记。

5. Obsidian 与临时文件

Obsidian 导出采用两阶段写入：先写临时文件，验证 Markdown、JSON 清单和附件完整后再替换最终文件。 只有导出完整后，系统才会清理下载的音频、视频和切片；应用服务启动时也会按保留期限清理异常退出后遗留的过期临时文件。

如果目标 Vault 暂时不可用，evey2obs 会保存本地待导出草稿，供之后仅重试导出。草稿状态只使用相对路径，过滤非必要元数据，不保存 API Key、Cookie、URL token、原始本地媒体路径或浏览器凭据。应用重启后，GUI “待导出草稿”窗口和 CLI export-list 只展示脱敏摘要、附件数量和本地草稿路径。

位置用途保留策略
Vault 笔记子目录 Markdown 笔记和 JSON 清单。 长期保留，由用户管理。
Vault 附件目录 原文图片。 长期保留，使用 Vault 内相对引用。
系统临时目录 下载媒体、标准化音频和切片。 成功导出后清理；失败文件按诊断保留期限处理。
系统缓存目录 按内容指纹保存 Whisper 转写与时间戳。 默认复用；用户可强制重新转写并覆盖，不包含原始媒体或凭据。
应用数据目录 / pending-exports Vault 导出失败后的 Markdown、JSON 清单和附件副本。 仅用于恢复导出；导出成功后自动删除，也可手动删除，可用 EVEY2OBS_RECOVERY_DIR 覆盖父目录。

6. 诊断报告

GUI 的“导出失败诊断”用于给用户或开发者定位失败任务。报告会脱敏本机路径和敏感字段， 但在分享前仍建议人工检查一次。 

{
  "task_id": "...",
  "source_type": "youtube",
  "status": "failed",
  "stage": "summarizing",
  "error_code": "LLM_FAILED",
  "next_action": "检查模型配置或稍后重试"
}

acceptance-run 生成的真实样例执行报告采用更严格的最小化字段：仅包含脱敏样例 ID、来源类型、提取方法、长度/附件计数、导出与清理布尔状态、稳定错误码和耗时。报告不保存 私有样例 URL、分享文案、正文、标题、本地媒体路径、Vault 路径、模型名或异常原文。 私有 real_samples.json 本身不受此脱敏保护，必须留在本机且不得提交。

7. 用户安全清单

  • 先用公开链接验证第一篇笔记，再处理批量队列。
  • 不要把真实 API Key 或 Cookie 写进截图、issue、测试夹具或聊天记录。
  • 遇到验证码、私密内容或付费内容时停止自动抓取。
  • 分享诊断报告前，检查是否仍包含个人路径、URL token 或账号信息。
