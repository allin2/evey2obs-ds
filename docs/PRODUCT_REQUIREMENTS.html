AI 多源内容总结与知识沉淀工具

产品需求文档 PRD 版本：1.0 日期：2026-06-17 状态：已确认需求基线 项目：evey2obs-ds
将 B站、YouTube、抖音、小红书、微信公众号和小宇宙的分享链接，统一转化为保留原文、可追溯、可直接写入 Obsidian 的结构化知识笔记。

1. 项目摘要

evey2obs-ds 是一个从零构建的多来源内容理解与知识沉淀工具。用户可以粘贴单个链接、整段分享口令或批量链接；系统自动识别来源，优先提取官方字幕或公开正文，必要时下载音频并本地转写，再由用户配置的大模型生成结构化总结，最终写入 Obsidian。

一句话定位

把散落在视频平台、公众号和本地文件中的内容，一键变成可信、结构化、可复用的个人知识笔记。

核心价值

  • 减少观看长视频、反复拖动进度条和手工摘录的时间。
  • 将不同平台内容统一为同一种笔记结构，降低整理成本。
  • 保留原始链接、时间戳和提取方式，避免摘要失去来源。
  • 本地优先处理音视频，大模型由用户自行配置，凭据不随内容输出。
  • 只负责高质量沉淀到 Obsidian；检索、追问和持续整理由 Obsidian 及其插件完成。

2.2 设计前提

  • 平台页面、字幕、媒体地址和风控规则会变化，所有平台实现必须独立适配且可替换。
  • 小红书等平台的分享链可能包含访问 token 与追踪参数；请求可需使用 token，但日志和笔记必须脱敏。
  • 微信公众号文章链接属于文章页面，应走 HTML 正文提取与图片理解，不应进入视频下载管线。
  • Whisper tiny 仅适合链路测试，对方言、背景音乐和低质量口播准确率不足；正式默认模型应为 small。
P0 依赖策略：yt-dlp 等平台提取依赖需要定期更新，不应长期锁定过期上限。新项目必须在引入平台能力时同时建立版本诊断与真实链接集成测试。

3. 产品定位

3.1 产品形态

首版是优先服务个人的本地桌面 GUI，保留 CLI 作为自动化和调试入口；安装、配置和交互不得假设用户是开发者，从架构上具备分发给其他人使用的能力。后续建立 Android 和 iOS 分享入口，复用统一任务协议和处理核心。

3.2 产品原则

  • 统一入口：用户不需要先判断平台或内容类型。
  • 来源优先：摘要必须保留原始链接、平台、标题和提取方式。
  • 本地优先：转写和临时文件默认在本机处理；在线 AI 总结可关闭。
  • 渐进降级：字幕、正文、音频、缓存、本地文件应形成可解释的兜底链路。
  • 公开内容：不绕过付费、私密、DRM 或账号访问控制。

3.3 产品目标与成功指标

目标首版指标
降低首次使用门槛新用户在 15 分钟内完成模型、Obsidian 配置和首篇笔记导出。

稳定沉淀内容成功任务 100% 生成包含原文、总结、关键观点、行动项和来源元数据的 Markdown。

5. 范围与边界

5.1 本期目标

  • 支持纯 URL、Markdown 链接、平台完整分享文案和多链接批量粘贴。
  • 稳定支持 B站、YouTube、抖音、小红书、微信公众号和小宇宙六个平台的公开内容。
  • 新增本地音频/视频导入作为平台解析失败的稳定兜底。
  • 保存清洗后的原始正文或完整转写、原文图片、AI 摘要、关键观点、行动项和来源元数据。
  • 统一生成结构化 JSON 与 Markdown，并将 Obsidian Vault 作为核心导出目标。
  • 提供单任务与批量队列，展示每项任务的进度、结果和失败原因。
  • 建立平台适配器和统一内容模型，降低后续新增来源的维护成本。

5.2 暂不承诺

  • 私密、好友可见、付费、会员、已删除或需要额外授权的内容。
  • 批量爬取账号历史内容、绕过平台频率限制或长期维护强爬虫。
  • 抖音直播、小红书直播、微信视频号直播的自动抓取。
  • 图片 OCR 和完整视频视觉理解；首版保存原文图片并预留处理接口，不承诺识别图内文字。
  • 多人协作、云端账号体系和商业化计费。
  • 内建向量检索、知识库问答或笔记长期整理；这些能力由 Obsidian 插件承接。

7. 核心用户流程

7.1 统一链接流程

首次配置模型与 Obsidian → 粘贴单个/批量链接或分享文案
→ URL 提取 → 平台与内容类型识别 → 元数据预检
→ 官方字幕/正文优先 → 音频 + Whisper 兜底 → AI 总结
→ 写入 Obsidian → 清理临时音视频
  1. 用户粘贴纯链接、Markdown 链接或完整分享口令。
  2. 系统提取第一个受支持 URL，显示识别到的平台。
  3. 系统解析短链，但保留平台访问所需的全部查询参数。
  4. 系统选择内容处理器：视频、文章或本地文件。
  5. 批量输入拆分为独立任务入队，单项失败不中断其他任务。
  6. 处理完成后展示标题、全文/文字稿、摘要、来源和导出位置，然后清理临时音视频。

7.2 链接失败兜底

链接解析失败 → 判断原因 → Cookie/重新复制分享链接/本地文件导入
→ 继续处理，不要求用户重新配置全部选项

9. 平台专项规则

9.1 小红书

  • 优先接受 App 复制的 xhslink.com 分享短链。
  • 短链跳转后的 xsec_token、type 等参数必须用于本次抓取，不能在请求前清理。
  • 缓存键使用笔记 ID；抓取 URL 与缓存键分离，避免把分享追踪参数写入文件名。
  • 分享链接可能包含 share_id、shareRedId、appuid 等追踪标识；日志和导出文件默认不保存这些参数。
  • yt-dlp 失败时，可读取公开页面中的 window.__INITIAL_STATE__，提取标题、描述和 H.264 masterUrl。
  • 裸笔记链接缺少 token 时，提示“请从小红书 App 重新复制分享链接”，不直接要求账号 Cookie。
  • 媒体签名 URL 可能过期，应在解析后立即下载，不长期保存下载地址。

9.2 抖音

  • 支持 v.douyin.com、douyin.com/video 和整段复制口令。
  • 首选音频或低体积媒体；保留标题、作者、时长和描述。
  • 游客态失败时才提示 Cookie 或本地文件导入。
  • 背景音乐占主导、无人声或方言场景应提示“文字稿可能不可靠”。

9.3 微信公众号

  • 仅处理 https://mp.weixin.qq.com/ 的公开文章链接。
  • 优先直接 HTTP 获取；必要时使用浏览器渲染，但不读取用户微信登录态。
  • 正文提取优先选择 #js_content 或 .rich_media_content，标题和作者使用结构化元数据与 DOM 双重兜底。
  • 处理懒加载图片的 data-src；保留正文内链接、列表、引用和表格。
  • 验证码、已删除、违规或仅微信内可见文章必须明确标记，不尝试绕过访问控制。
  • 默认保存清洗后的完整正文、图片、AI 摘要、关键观点、行动项和原文链接。

9.4 小宇宙

  • 首版仅处理公开单集分享链接，不批量抓取播客全部历史节目。
  • 优先提取节目简介、show notes 和平台提供的官方文稿；无可用文稿时下载音频并使用 Whisper。
  • 音频下载必须显示已下载大小、总大小、速度和预计剩余时间。
  • 节目处理完成并成功导出后删除下载音频，保留完整转写和分段时间戳。

10. 交互与界面需求

10.1 主界面

  • 输入框名称由“视频链接”改为“链接或分享口令”。
  • 输入框支持换行粘贴多个链接；提交前显示已识别条数和重复项。
  • 提供“选择本地文件”按钮，与链接入口并列。
  • 粘贴后实时显示平台图标/文字、内容类型和解析状态。
  • 主界面可选总结模板和 Obsidian 子目录；模型连接与 Vault 位置在“设置”中统一管理。
  • Cookie 配置放入“高级设置”，避免给普通用户造成前置负担。

10.2 首次配置

  1. 设置大模型协议、Base URL、API Key 和模型名，点击“测试连接”后才标记为可用。
  2. 选择 Obsidian Vault 与默认子目录，系统验证路径可写并生成一篇可删除的测试笔记。
  3. 选择 Whisper 模型，建议默认 small；清楚展示首次下载所需空间。
  4. 完成后进入主界面，配置可随时修改，不与单个任务绑定。

10.3 任务队列与状态

任务必须使用稳定阶段，不以原始第三方日志作为唯一反馈：

正在识别来源
正在解析分享链接
正在获取字幕/正文/音频
正在转写 3/8
正在生成总结
正在导出到 Obsidian
处理完成 / 已取消 / 处理失败
  • 队列列表固定展示标题/链接、平台、当前阶段、总进度、耗时和操作。
  • 下载阶段展示百分比、速度和 ETA；转写阶段展示已处理时长/总时长。
  • 用户可取消单项、重试失败项或清理已完成记录。

10.4 结果页

  • 展示标题、平台、作者、来源链接、提取方式、全文和摘要。
  • 提供打开 Markdown、复制摘要、打开原文、打开 Obsidian 四个动作。
  • 展示准确性提示，例如“来自自动字幕”“来自 Whisper tiny”“仅提取文章正文”。

  • 首版不引入云端账号系统；移动端方案可在本地处理与用户自托管处理节点之间另行评估。

12. 数据模型与输出

12.1 统一内容模型

{
  "id": "platform-content-id",

15. 验收标准

15.1 通用验收

  • 纯 URL、Markdown 链接和完整分享文案均能正确提取链接。
  • GUI 与 CLI 使用同一条业务管线，结果一致。
  • 大模型设置可测试，Obsidian Vault 路径可验证，配置错误不会启动批量任务。
  • 批量粘贴至少 10 个链接时能正确入队，单项失败不中断队列，可单独重试。
  • 每个成功任务生成结构化 JSON 与 Markdown，包含原文/完整转写、AI 摘要、关键观点、行动项、标签和可追溯来源。
  • 图文内容的图片保存在 Vault 附件目录并可在 Obsidian 正常显示。
  • 导出成功后临时音频、视频和分片全部清理，原文、图片和笔记不受影响。
  • 任何错误都不会输出 API Key 或 Cookie。
  • 所有单元测试、lint/语法检查通过。

17. 风险与设计决策

风险影响应对
平台页面和提取器频繁变化下载能力突然失效保持 yt-dlp 更新；适配器隔离；本地文件兜底。
分享 token 和媒体签名过期旧链接无法处理立即解析下载；提示重新复制链接。
Whisper 小模型误识别摘要建立在错误文本上默认 small；输出模型与置信提示；无人声检测。
Cookie 涉及账号凭据隐私和安全风险默认不用；明确授权；本地读取；不写日志。
公众号反爬或验证码正文提取失败浏览器渲染或复制全文兜底，不绕过访问控制。
小宇宙公开接口或媒体地址变更单集解析或下载失败独立适配器、固定夹具测试、快速更新，并允许用户导入本地音频。
批量任务占用过多 CPU、内存和磁盘界面卡顿或任务失败重型转写默认串行，入队前检查磁盘，导出后即时清理。
版权与长期存储内容使用边界不清面向个人学习；保留来源；默认不公开再分发全文。

已确认决策

  • 首版优先服务个人，但产品必须可安装、可配置、可分发给其他用户。
  • 首版交付本地桌面 GUI 并保留 CLI；后续建设 Android 和 iOS App。
  • 本项目写入 Obsidian，不内建检索、追问和持续知识整理能力。
  • 六个平台全部属于首版功能范围，允许按阶段实现，发布前必须全部验收。
  • 官方字幕或正文优先，音频 + Whisper 兜底；导出成功后自动清理临时音视频。
  • 笔记保存完整原文/转写、原文图片、AI 摘要、关键观点、行动项和来源元数据；首版不做图片 OCR。
  • GUI 同时支持单链接与批量队列，每项拥有独立进度与失败原因。

建议默认值（非不可变需求）

  • Whisper 默认使用 small，用户可为性能或准确率改用其他模型。
  • 批量队列默认单个重型转写任务运行，轻量解析可有限并发。
  • 大模型使用全局默认配置，后续可增加单任务覆盖。
  • 产品工作名使用 evey2obs，对外发布前可另行确定正式品牌名。

18. 完成定义

本期需求只有在以下条件全部满足后才算完成：

  • 六个平台和本地文件拥有明确、互相隔离的处理策略。
  • 整段分享文案可以直接粘贴，无需用户手工裁剪 URL。
  • B站、YouTube、抖音、小红书、公众号和小宇宙均有真实公开样例验收记录。
  • 单链接与批量队列可用，每项任务的进度、取消、失败原因和重试行为通过验收。
  • 平台失败时提供可执行的下一步，不只显示第三方堆栈。
  • 输出包含完整原文/转写、原文图片、摘要、关键观点、行动项、来源、提取方式、模型和准确性说明。
  • 成功任务的临时音视频已清理，文字与 Obsidian 附件仍完整可用。
  • 浏览器 Cookie、API Key 和分享追踪参数不会进入日志或笔记。
  • B站、YouTube、AI 总结、Obsidian 和清理等新实现能力均有独立测试与端到端验收记录。
  • README、环境示例、用户手册、测试和依赖版本同步更新。
建议的首个交付切片：统一输入、内容模型、任务状态机和结构化错误。这一步先固定所有平台都要复用的输入、进度、产物与失败契约，再从零接入第一个平台。
