# evey2obs-ds 从零实施计划

## 实施原则

本项目只以 `docs/PRODUCT_REQUIREMENTS.html` 为产品需求基线，以 `docs/ARCHITECTURE.md` 为技术边界。
不读取、复制、导入、兼容或对照任何旧项目代码。

每个阶段按以下循环执行：

```text
阅读 PRD 与项目状态 → 选择最小未完成切片 → 只读规划
→ 测试先行 → 实现 → 验证 → 只读审查 → 更新项目状态
```

## 阶段 0：核心契约

**目标：**先定义平台、UI 和基础设施共同依赖的稳定语言。

- 定义 `SourceInput`、`ContentDocument`、`SummaryResult`、`Task`、`ExportResult`。
- 定义来源类型、内容类型、任务阶段、任务状态和稳定错误码。
- 定义平台适配器、转写器、总结器、导出器和清理器协议。
- 定义进度事件和取消语义。
- 为所有领域契约增加单元测试。

**退出条件：**不连网、不调用外部程序即可验证数据、状态和错误契约。

## 阶段 1：配置、存储与导出

**目标：**先打通不依赖平台的本地产物链路。

- 实现类型化配置、环境变量覆盖、密钥脱敏和设置验证。
- 实现 Obsidian Vault 与子目录校验。
- 实现 Markdown frontmatter、笔记正文和附件相对链接。
- 使用两阶段原子写入，失败时不损坏已有笔记。
- 使用临时 Vault 完成端到端导出测试。

**退出条件：**使用固定 `ContentDocument` 和 `SummaryResult` 可生成完整 Obsidian 笔记与附件。

## 阶段 2：媒体、转写与 AI 总结

**目标：**建立平台无关的媒体处理管线。

- 实现 ffmpeg 可用性诊断、音频提取、切片与临时目录管理。
- 实现 Whisper 模型选择、首次下载提示、分段转写和缓存。
- 实现 OpenAI-compatible 与 Anthropic-compatible 总结接口。
- 实现长文分块总结、结构化输出验证和失败保留原文。
- 实现成功导出后清理，失败时按保留期限清理。

**退出条件：**本地 MP3/MP4 可完成转写、总结、Obsidian 导出和媒体清理。

## 阶段 3：首批视频来源

**目标：**实现 B站与 YouTube，验证平台适配器契约。

- 实现统一 URL/分享文案提取与来源识别。
- 两个平台均使用官方字幕优先、音频 + Whisper 兜底。
- 实现 Cookie、代理、403、SABR、地区限制和登录要求的结构化错误。
- 为适配器建立脱敏夹具与可选真实链接测试。

**退出条件：**有字幕与无字幕样例均通过字幕/转写分支验收。

## 阶段 4：短视频与图文来源

**目标：**实现抖音和小红书。

- 支持整段分享文案、短链与访问 token。
- 抖音视频走字幕优先、音频兜底。
- 小红书支持视频与图文，保存正文图片，首版不做 OCR。
- 对分享参数、日志、文件名与输出元数据进行脱敏。

**退出条件：**两个平台的公开视频及小红书图文样例通过验收。

## 阶段 5：文章与播客来源

**目标：**实现微信公众号与小宇宙。

- 公众号提取标题、作者、时间、正文、图片与链接，转为 Markdown。
- 小宇宙提取节目元数据、show notes、官方文稿或音频。
- 实现文章与播客专用总结模板。
- 验证长文、长音频、超时、取消和恢复。

**退出条件：**纯文字/含图文章与有/无文稿播客全部通过。

## 阶段 6：桌面产品化

**目标：**交付可安装、可配置、可分发的桌面工具。

- 实现首次模型连接测试、Whisper 模型设置与 Vault 校验。
- 实现单链接、批量队列、进度、取消、重试和结果操作。
- 不向用户直接暴露第三方堆栈与原始日志。
- 完成 macOS 打包和 Windows 路径/打包预验证。
- 完成安装、升级、隐私、故障排查和用户手册。

**退出条件：**六个平台通过 PRD 验收，新用户可在 15 分钟内生成首篇笔记。

## 阶段 7：移动端准备

- 版本化任务命令、进度事件和结果协议。
- 评估 Android/iOS 本地处理与用户自托管节点。
- 实现“分享到 evey2obs”的最小原型。

## 每个切片的完成定义

- 代码只依赖当前项目和明确声明的第三方依赖。
- 核心行为有单元测试，外部适配有脱敏夹具测试。
- 真实网络测试与默认测试隔离。
- pytest、ruff 和适用的类型/构建检查通过。
- 凭据、Cookie、追踪参数和真实 Vault 数据不进入日志、夹具或 Git。
- `docs/PROJECT_STATUS.md` 更新为实际已验证状态。
